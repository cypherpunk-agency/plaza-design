# Capsule and Sandbox endpoint dependencies

Capsule and Sandbox now declare `needs.devices: []`: neither simulation requires a fixed historical inventory of endpoint IDs. Capsule's configurable controller still validates its actual router/Pixel, state, tuning and reply references. Sandbox retains its pulse presentation effect and night observation. Source-only static prompt/goal/state requirements were removed; actual source references remain validated. The central native gameplay declaration floor was not changed in this slice.

Capsule accepts its actual pending device source before geometry. It reconstructs Concierge conversation metadata from the existing shared conversation source. Sandbox passes its existing data argument through pending/private-Play registration and native preview and projects shared scalar defaults before geometry. Both retain native target validation contexts and CRUD capability metadata.

Geometry iterates actual source endpoints. Existing artwork may supply a default anchor when present; an explicit manifest device binding takes priority. Missing old machine artwork falls back to the endpoint's own declared spot. New endpoints no longer require membership in an original device list. Physical primitive anchors remain explicit: Capsule's shell/door/window/router/desk/sun-patch inputs and Sandbox's reset/window/zones/station signs are preserved.

Sandbox's visual snapshot derives machine spots from present artwork definitions and resolved rows, rather than the old device inventory. Removing an endpoint does not require destroying its decorative picture. An orphan button-counter conduit skips drawing when its required visual spots are absent. This is presentation only; no gameplay evaluator, state owner or source alias was introduced.
